Date: 2026-09-29

## Decision legend and evidence levels

- **Retain**: keep the item and its distinct behavioral obligation.
- **Merge**: keep the behavior, but route duplicated orchestration through one existing implementation after equivalence is demonstrated.
- **Replace**: retire the item only after the named replacement produces equal or stronger evidence on the same subject.
- **Delete**: safe only when no distinct behavior remains. This inventory finds no Goal 0006b test or journal that is presently safe to delete.
- **E0**: static/schema/unit support; useful regression evidence, not native acceptance.
- **E1**: live generic daemon/Control or refusal evidence, without an installed qualified A/B native boundary.
- **E2**: production-binary platform witness (legacy Linux v1 or Windows).
- **E3**: installed Linux amd64 A/B production witness with real cgroup-v2, exact peer checks, authentic Claim, and, where applicable, real Pi/OpenCode.
- **E4**: acceptance package for one clean exact commit, including E3 positives, platform negatives, sanitized evidence, and independent review. No current job by itself is E4, and the dirty baseline cannot be an E4 subject.

Refusal evidence is never promoted to positive capability evidence. WSL2 denial, rootless Compose denial, unprovisioned-host denial, host prerequisite probes, Pi provider smoke, and OpenCode synthetic smoke are not substitutes for qualified A/B Pi/OpenCode/replay positives.

## Findings that control consolidation

1. **None of the three questioned fault families leaves unresolved containment after its test completes.** Receipt-persistence failure first proves the unchanged unresolved journal, then restores Store permissions and performs same-RunKey receipt-backed release (`daemon/e2e/production_linux_v2_owner_cli_test.go:4010-4147`). Helper `stop` and `ack-stop-receipt` response loss replay to the stage's required `released` state; `launcher-ready` explicitly requires `released` or `pre_gate_released`, an exact no-checkout clone abort, and a release tombstone (`:3430-3678`). Helper exit requires anchor wait/reap, a valid mirror StopReceipt, absent leaf, cleared owner fields, and `RecoveryState: released` (`daemon/e2e/production_linux_v2_helper_exit_witness_test.go:270-330,694-773`). These cases do not need independent guests for containment uncertainty.
2. **The actual shared-StateDir gap is the next-fixture admission predicate, not those recovery paths.** Every hidden owner witness seeds a Claim with `LocalState` `claiming`/`claimed`, and the witness has no terminal-transition mutation (`daemon/internal/app/linux_owner_witness_linux.go:2726-2771,3671-3714`). Successful physical stop leaves a release tombstone (`:3220-3231`). The next fixture nevertheless accepts prior records only when `TerminalState != ""` through `isStoppedRetained` (`daemon/e2e/production_linux_v2_owner_cli_test.go:1985-2048`). Therefore the first journal-producing shared witness can leave a physically released, nonterminal retained record that the next witness refuses, even though Goal 0006b explicitly distinguishes physical release from completed checkout/terminal cleanup. Isolating receipt/helper cases would hide this broader mismatch; the minimal correction is for fixture admission to recognize an exact physically released retained record without treating it as terminal or deleting it.
3. **The independent-guest design for genuinely unresolved/incompatible cases is deliberate and must survive.** The workflow invokes the acceptance script once per case set (`.github/workflows/ci.yml:105-139`); every invocation creates a new rootfs and systemd guest (`scripts/ci/linux-v2-native-acceptance.sh:66-76,744-801`). Separate case sets cover `create_started`, `leaf_bound`, `launcher_bound`, ACK-loss `launcher_bound`, stale leaf, migration, the four stale-journal variants, and synthetic cleanup's empty-Store precondition. Do not merge them into one guest and do not erase a journal to admit the next case.
4. **The source-subject check is duplicated and does not bind built bytes to `GITHUB_SHA`.** Native and rootless each embed roughly 40 lines that verify `HEAD`, enumerate the committed tree, and calculate the same custom tree digest (`scripts/ci/linux-v2-native-acceptance.sh:836-895`; `scripts/ci/rootless-compose-native-acceptance.sh:140-181`). Neither rejects staged, unstaged, or untracked source. Both later label evidence with `GITHUB_SHA`, while their Go/C builds consume working-tree files. Native is worse ordered: it builds production binaries before calculating the subject (`linux-v2-native-acceptance.sh:257-280,836-895`); rootless checks the committed subject before its build but still allows dirty working-tree bytes (`rootless-compose-native-acceptance.sh:140-193`). Replace both inline blocks with one `scripts/ci/linux-v2-source-subject.py` that emits strict JSON `{commit, tree_digest}`, requires exact `HEAD == expected SHA`, and rejects staged, unstaged, and untracked source before any build, download, migration, credential staging, guest/container creation, or other fixture effect. This is an E4 subject-binding blocker.
5. **StateDir is aligned for installed A/B witnesses.** The installer reads the canonical StateDir from `/etc/symmetry/daemon.json` and writes it into the v2 owner config (`scripts/install-linux-owner.sh:420-434,602-646`). The native fixture pins `/var/lib/symmetry-v2`, provisions its Store layout, and uses it in generated configs (`scripts/ci/linux-v2-native-acceptance.sh:400-462,899-1053`). The production fixture rejects any config/OwnerConfig mismatch (`daemon/e2e/production_linux_v2_native_witness_test.go:1720-1748`). The cleanup witness independently requires the same path (`daemon/e2e/production_linux_v2_cleanup_witness_test.go:37-41,194-215`).
6. **The rootless StateDir names are aliases, not divergent Stores.** Each daemon container uses `/var/lib/symmetry`, backed by a distinct host directory; the read-only observer mounts those host directories at `/var/lib/sym-pi` and `/var/lib/sym-oc` (`scripts/ci/rootless-compose-native-acceptance.sh:20-24,191-255,430-459`). Keep the mapping because the test reads each App-owned RunJournal while the exact terminal response is held (`daemon/e2e/production_linux_v2_rootless_compose_witness_test.go:245-318,747-781`).
7. **Journal retention is tested correctly in code but fixture teardown can erase the containing guest.** Native cleanup removes the entire private rootfs after export (`scripts/ci/linux-v2-native-acceptance.sh:151-231`), and the Compose job removes its temporary state tree (`.github/workflows/ci.yml:2380-2427`). Those paths can contain retained or unresolved RunJournals. This must not be treated as journal retirement or containment proof. No consolidation may add `rm`, `RemoveAll`, Store reset, or journal deletion to make a later case pass. Raw journals should remain in protected recovery storage; public artifacts must remain derived and credential-free.
8. **There is one centralized v2 exporter, but an older raw-evidence path.** Installed A/B and rootless Compose both use `scripts/ci/export-linux-v2-redacted-evidence.py`, with strict allowlists, duplicate-key rejection, secret-value scanning, forbidden-key rejection, and manifests declaring no raw journals (`:18-116,118-198,200-312`). Per-test Go writers are evidence producers, not competing exporters. In contrast, the legacy Linux integration witness embeds `raw_journal_snapshots` (`daemon/e2e/production_linux_containment_replay_witness_test.go:71-100`) and CI uploads witness JSON plus raw stdout/stderr (`.github/workflows/ci.yml:2049-2140`). Retain that E2 regression suite, but do not admit its current upload as sanitized E4 evidence.
9. **Host setup and cleanup are duplicated for different trust boundaries.** The host prerequisite probe, installed A/B guest, rootless Compose, and manual WSL2 denial use different identities and lifecycle authorities. Their teardown checks are not interchangeable with a containment StopReceipt. Only small pure helpers (source-subject binding, pinned tool acquisition, Go event checking, and sanitized export) should be shared.

## Minimal consolidation plan
