## Public/API shape

- **HTTP surface**: unchanged routes, unchanged content types accepted for every documented
  producer. The machine API and portal API accept `application/json` and
  `application/vnd.symmetry+json` (and `application/*+json`) exactly as before; `urlencoded` forms
  and the strict duplicate-member plug behave as before. What changes is the *refusal class* for
  `multipart/form-data` on a mutation route: it is no longer parsed at all — the body is left to
  `Plug.Parsers`' `pass: ["*/*"]` arm, so no multipart part framing is charged against a length
  limit anywhere in the stack (the CVE's own surface). The probe records the post-change class per
  route: `body_params` stays `%Plug.Conn.Unfetched{aspect: :body_params}` and the route refuses in
  its own terms (`401` for the three authenticated mutation routes, `422` for the login form).
- **Dependency surface**: `plug ~> 1.20` resolves to 1.20.4; `telemetry_metrics` and
  `telemetry_poller` are no longer resolvable names in this project's lock; `:telemetry` (base) stays
  as a transitive dependency; `credo` is available in `:dev` and `:test` only, never in a release.
- **Module surface**: `SymmetryControlWeb.Telemetry` no longer exists; the supervised child list
  starts at `SymmetryControl.Repo`. No other module's public function changes.

## Exact edge-case semantics

- **Multipart bodies are not parsed, and nothing reads them.** With no matching parser and
  `pass: ["*/*"]`, `Plug.Parsers` returns the connection with `body_params` unfetched; the
  strict-JSON plug only inspects `application/*+json` bodies, and every controller on a mutation
  route reads its body through that plug or through the JSON decoder. The deleted parser therefore
  removes a parse surface nothing in the repository exercised; no controller gained or lost a branch.
  This is verified by probe, not assumed: a throwaway script drives a multipart POST through the
  endpoint and records the refusal status (see *Evidence plan*, step 7).
- **`urlencoded` stays.** Its producer is a tracked CI script (owner-claim enrolment), and the plug
  test pins urlencoded delegation (`strict_evidence_json_test.exs:135-139`). Removing it would
  weaken a live input path, so the contract's "remove `:multipart`" is read exactly: one parser
  gone, the others untouched.
- **The telemetry child is deleted, not replaced.** The module returned an empty measurement list
  and `metrics/0` had no consumer; there is no metric, reporter, dashboard or alert to re-point, so
  deleting the child and both deps is the whole change — no `:telemetry` handler is added to
  "preserve" behaviour that no consumer observed. `:telemetry.execute/3` emissions in
  `Orchestration`/`Goals` stay (base library, pinned separately in `orchestration_telemetry_test.exs`).
- **`mix deps.unlock --unused` is a mutation, not a check.** Per review amendment P3-8 the
  acceptance is re-worded: the check is that no remaining reference to `telemetry_metrics` or
  `telemetry_poller` exists in `control/mix.lock`/`control/mix.exs` — not "the tree", which the
  0005 archive mention and this document's own prose match by design — and the re-run printing
  nothing (its locked set already pruned) is the auxiliary observation, not a green check by itself.

## Design trade-offs and decisions

1. **Delete the module and both deps rather than keep an empty supervisor.** Keeping a child that
   supervises nothing is the dead weight the slice exists to remove; a future metrics story re-adds
   a reporter deliberately rather than inheriting a stub that names its own deps in comments.
2. **Add `credo` as a plain dev/test dep, no alias or config.** W1-01 owns `control/.credo.exs` and
   the CI step; W1-02 supplies only the dependency the plan pins (`~> 1.7`, `runtime: false`). No
   second convention, and nothing in this slice can make a gate blocking.
3. **Remove exactly one parser from the endpoint list.** The plug's own local option replica in
   `strict_evidence_json_test.exs:10,169` still names `:multipart`; the conductor amendment
   (simplify RFW102S-3) extends the owned set to that file for one added regression case that pins
   "the endpoint no longer parses multipart bodies" at the endpoint. The replica spelling stays
   recorded drift for the file's owner (RFW102-1), not silently "fixed" — and not a reason to touch
   the case that pins plug delegation.
4. **No advisory suppression and no lock hand-editing.** The bump comes from `mix deps.get`
   resolving `plug ~> 1.20`; `hex.audit` exit 0 is the evidence, not a curated advisory list.
5. **The plan document itself is the only new file.** The evidence runs are one-off commands; a
   committed harness or evidence record would be new dead weight for a slice this size (the merged
   shape reference does the same: `docs/plans/2026-11-20-provider-action-chain-removal-plan.md`).

## Residual risks

- The plug test's local option replica keeps the stale `:multipart` spelling; the one added
  regression case pins the endpoint's behaviour, so a reader no longer has only prose to trust.
- Multipart semantics for a hypothetical future producer change from "parsed, then validated" to
  "not parsed"; the committed case records today's refusal class, so a future producer's failure is
  diagnosed from a red pin rather than from this plan.
- `plug` 1.20.4 is three days old on this host's clock; the lock pin and the advisory-free audit are
  the evidence, and a later fix would be a new bump, not a suppression.
- The full control suite is not run in this stage by design; the conductor's gate-runner owns it, and
  a failure it finds there is reported against this change rather than assumed impossible.
